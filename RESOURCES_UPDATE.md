## Install

From the repository root on Ubuntu/WSL (Node.js 22):

```bash
git switch main
git pull --ff-only origin main
git switch -c feature/resources-page
# Replace the ZIP path with the actual download location.
unzip -o /path/to/mcmu-resources-update.zip -d .
node scripts/apply-resources-update.mjs --dry-run
node scripts/apply-resources-update.mjs
npm run check
```

The installer checks the source anchors and JavaScript syntax before writing the four existing integration files. It is safe to rerun. If your source differs, it stops rather than overwriting the renderer. The ZIP contains only new resource files, tests, this guide, and the installer; no existing tour audio, metadata, images or transcripts are replaced. Review `git diff` and `git status` before committing. If testing fails because a local content update has introduced Windows metadata files, remove only those artifacts (`find public/content -type f -name '*:Zone.Identifier' -delete`) and rerun the check.

Start the dev server (`cd server && npm install && npm start`), then open http://localhost:3000. Test both languages. The new last menu entry opens `#/resources`; the next-stop button on Closing Remarks also opens the resource page. The existing menu and settings are reused. Switch languages from the Resources page and confirm the page remains open; open/closed categories are preserved during the switch. Click each featured question and expand all five categories; links should open official CMU pages in new tabs. The page has no audio, progress bar, transcripts or story carousel. No dummy media is required. If embedding in a sandboxed iframe, the parent must allow popups for the external links.

To publish after review:

```bash
git add public/index.html public/src/content-manifest.js public/src/router.js public/src/render.js public/src/resources.js public/resources.css public/content/metadata/resources.json public/content/resources/stop--resources--001.jpg tests/resources.test.mjs scripts/apply-resources-update.mjs RESOURCES_UPDATE.md
git commit -m "Add multilingual Resources and Next Steps page"
git push -u origin feature/resources-page
```

Merge the feature branch into main through a PR. The existing GitHub Pages workflow builds the regular content manifest, runs tests, and publishes the Resources files as part of `public/`. No server dependency or CI change is required.

## Future content updates

Edit `public/content/metadata/resources.json`. This is the sole source for the Resources menu title, page heading, section headings, FAQ labels, group names, link labels and URLs, hero path and image alt text. `featured` entries reference existing category-link IDs, so URLs only live in one place. The `categories` array controls group order and its `links` arrays control link order. Keep IDs stable and unique, use one of `cost`, `academics`, `housing`, `community`, `visiting` for the icon, and use an HTTPS URL on cmu.edu or its subdomains. No descriptions or footer are included, per the supplied mockup instructions.

The photo is in `public/content/resources/`, outside the audio-stop compiler's managed media folders. This avoids needing a stop TSV record or narration. Replace it in that folder using a lowercase filename and update `hero.src` and `hero.alt` if necessary. Update the alt text in this JSON, not `image-alt.json`, which applies to the managed photo catalog.

To add another language, enable it using the existing `ui.json` workflow and add the new language code to each translated object in `resources.json` (e.g. `"ko": "..."`). Keep the `en` labels. Any missing localized resource label falls back individually to English; all current English and Simplified Chinese labels are provided. URLs and category/link IDs are shared across languages. No JavaScript change is necessary. Official destination websites may themselves be English-only.

After any change run `npm run check` and reload the app. Resource-specific validation is in `tests/resources.test.mjs` and the shared runtime validator in `public/src/resources.js`. `generated.json` is still generated by the existing audio content compiler and must not be edited. The Resources JSON is deliberately loaded separately; tests verify its schema, links, hero file, translations and integration. The tests do not attempt to verify live destination availability.
